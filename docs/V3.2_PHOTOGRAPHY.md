# v3.2 — Gemini Aviation Photography

v3.2 keeps Telegram as the user interface and adds a Gemini-driven photography subsystem.

## User flow

- `/camera` — type any camera body name in natural language. Gemini resolves a conservative hardware profile and stores it per Telegram user.
- `/lens` — optionally add the aircraft lens. Gemini resolves focal range/aperture/stabilization without inventing uncertain specifications.
- `/conditions` — view measured weather, atmospheric clarity, solar geometry, and the transparent heat-haze diagnostic.
- `/photo` — combine the saved gear, current location, live ADS-B aircraft, Open-Meteo weather/air-quality data, and sun geometry; Gemini 3.8 Flash then returns one primary shooting setup.
- Every aircraft alert includes **📷 Best camera settings**, targeting that notification's aircraft when it is still visible to the providers.

## Data / reasoning boundary

Deterministic code is responsible for measurements and geometry only: aircraft position/velocity, weather, air quality, sun position, bearing and a transparent heat-haze signal. It does **not** hard-code final shutter/aperture/ISO decisions.

Gemini is responsible for the photography decision. The final response uses structured JSON validated by Pydantic and includes shutter speed, aperture, ISO strategy, autofocus, AF area, drive mode, stabilization, focal length, metering, white balance, file format, timing, technique and warnings.

If Gemini cannot return a valid structured answer, v3.2 fails explicitly instead of silently substituting canned settings.

## Atmospheric inputs

Open-Meteo Weather supplies temperature, humidity, dew point, precipitation, cloud cover, visibility, wind/gusts, surface pressure, solar radiation, direct normal irradiance, diffuse radiation and—when the selected weather model exposes it—surface/soil temperature.

Open-Meteo Air Quality supplies aerosol optical depth, dust, PM2.5, PM10 and UV index. AOD is particularly useful because it describes whole-column aerosol haze.

The heat-haze diagnostic combines measured warmth, ground-air temperature difference, solar loading, wind and visibility into a 0–100 signal. Gemini receives both the raw values and that signal; the signal is not itself a camera-settings engine.

## Deployment

Northflank runs two independent always-on services built from the same Dockerfile:

1. `Aircraft Web` — FastAPI + Telegram polling + Gemini photography commands.
2. `Aircraft Worker` — the 5-second ADS-B monitoring/notification loop.

Both use the same managed MongoDB addon. GitHub Actions supplies secrets to Northflank without committing them.
